# Chorify 视频复刻双表单重构实施计划

## Global Constraints

- 表单一和表单二都作为 AI 对话中的工具消息，普通消息、工具表单与底部输入框共享现有 Chat 内容轨道；打开工具前后不得改变聊天主栏、背景或输入框宽度与视觉。
- 表单一只定义总体复刻意图；表单二只确认 AI 分析后的视频对象替换清单。
- 正式确认表单二之前不创建候选视频，不打开视频管理区；选择候选后才打开最右视频详情。
- 当前为纯前端演示，不接真实 AI、上传、产品库、积分或后端任务；解析与分析必须使用确定性状态转换。
- 保留现有候选卡片/表格双视图、审核、版本和导出行为。

### Task 1: 重构双表单状态模型

- 先在 `tests/marketing-factory-model.test.mjs` 与 `tests/marketing-factory-two-stage.test.mjs` 增加失败测试，再修改模型。
- 将订单配置拆为 `intentDraft`、`referenceAnalysis`、`replacementPlan`，阶段保持 `intake → intent_review → analyzing → plan → running`。
- 表单一支持必填参考视频、可选三种快捷方式、可选目标国家/目标商品、人物/场景/片段三态策略、自然语言解析、理解摘要和冲突处理。
- 未选择快捷方式时商品和国家保持不变，但人物、场景、片段仍可调整。
- 表单二包含商品、本地化、人物、场景、片段五组映射；同一人物跨镜头聚合，主商品全部露出统一替换，场景组与时间片段独立。
- 实现 `parseReplicationIntent()`、`updateReplacementMapping()`、`applyReplacementGroupRule()`、`updatePlanFromNaturalLanguage()`；调整分析、确认和重新配置接口。
- 阻塞项清零后才能确认；候选数支持 1/3/5；重开表单一保留旧分析记录并使当前替换清单失效。

### Task 2: 重构双表单对话界面与事件联动

- 先在 `tests/marketing-factory-view.test.mjs` 增加失败测试，再修改视图和事件。
- 表单一标题为“定义这次要怎么复刻”，使用紧凑 B 端单容器、清晰分隔和三态矩阵；支持上传/链接、快捷方式、条件字段、自然语言识别和 AI 理解摘要。
- 表单一提交后折叠为摘要；分析进度使用普通 AI 消息；分析完成后在下方追加“确认替换清单”工具卡。
- 表单二按五组折叠，默认只展开需处理组；对象使用紧凑的“原对象 → 目标对象”映射行，展开后显示截图、出现位置、推荐理由、目标来源与镜头例外。
- 底部显示 1/3/5 候选数、预计时间和积分；阻塞项存在时禁用“确认替换方案并开始复刻”。
- 表单二支持自然语言更新并高亮受影响映射，但不直接生成。
- 保持 Chat 宽度、背景与输入框不变；长表单随对话区滚动。

### Task 3: 更新产品文档与完成验收发布

- 更新外层项目的现行视频复刻产品逻辑和高保真设计文档，记录双表单结构、状态、确认门禁与 2026-08-17 变更。
- 建立并完成对应 change package，运行 `node tools/docs-governance.mjs build` 与 `node tools/docs-governance.mjs check`。
- 运行完整 Node 测试，并在 1920×1080、1366×768 下完成浏览器验收：欢迎态视觉不变、表单一、分析、表单二、阻塞解除、1/3/5 候选、卡片/表格管理、候选详情。
- 提交并推送当前 GitHub 分支，更新现有 Vercel 公开 Demo，验证公开链接可访问。
